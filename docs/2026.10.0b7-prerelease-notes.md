# Grainfather Integration 2026.10.0b7 — MQTT diagnostics

## Scope
Diagnostic-only follow-up to 2026.10.0b6 for failed supervised target writes on GF30.

## Changes
- Log at DEBUG when a confirmed temperature target command is prepared, with the requested temperature and previous MQTT-event timestamp.
- Log at DEBUG when the MQTT PUBLISH has drained locally. This is **not** proof of broker acceptance or controller execution.
- Log at WARNING when the 10-second fresh-readback check times out, including the requested target, prior/latest MQTT-event timestamps and latest reported target.

## Not changed
- MQTT command 0, command topic, payload, QoS, or timeout.
- No bypass of fresh readback verification.
- No automatic retry or new control paths.

## Observed pre-release failure
A requested 21.5 C returned a timeout; both the physical controller and HA continued to show 17.0 C. MQTT broker connection and SUBACK appeared healthy; event age was stale at later observation. These observations do not prove that the controller accepted the command.
