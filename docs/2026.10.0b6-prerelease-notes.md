# Grainfather Integration 2026.10.0b6

## Summary

This beta fixes a GF30 MQTT cold-start issue where Home Assistant could load the
integration successfully but live GF30 MQTT telemetry would not begin until the
integration was manually reloaded.

The fix keeps the existing REST discovery and MQTT runtime architecture, but
makes MQTT startup self-healing.

## What was happening

The integration previously created the ESP MQTT subscriber only once during
`async_setup_entry()`, immediately after the first Grainfather REST refresh.

If the first refresh did not yet expose the GF30 ESP chip ID, no MQTT subscriber
was created. Later coordinator refreshes could discover the device correctly,
but there was no path that created MQTT afterwards.

A manual Home Assistant integration reload repeated the startup sequence after
the Grainfather API/network had stabilized, which is why telemetry then started.

There was also a second cold-start dependency: live telemetry command 23 was
normally sent only after receiving a controller `status=online` MQTT message.
If Home Assistant subscribed after that status publication, live events could
remain absent even though the broker subscription itself was healthy.

## Fix 1: MQTT reconciliation after REST refresh

The integration now reconciles ESP MQTT state whenever the Grainfather
coordinator receives a new REST snapshot.

If a usable ESP chip ID appears after startup, MQTT is created and started
automatically without requiring a config-entry reload.

The reconciliation is idempotent:

- a healthy subscriber with the same chip IDs is kept;
- a stopped subscriber is recreated;
- changed chip IDs cause the old subscriber to stop before replacement;
- missing account/chip information remains fail-passive.

## Fix 2: Proactive telemetry request after SUBACK

After a successful MQTT SUBACK, the client now immediately sends the existing,
field-verified Grainfather telemetry command 23 using the short initial
subscription window.

This removes the dependency on receiving a retained/initial online-status
message before requesting live telemetry.

The existing status-driven and periodic keepalive behavior remains in place.

## Safety boundary

No new controller command type was added.

Outbound MQTT remains limited to the already field-verified commands:

- command 23 — telemetry subscription maintenance;
- command 0 — explicitly confirmed GF30 target-temperature write.

The cold-start fix does not add heater, cooling, pump, control-mode or profile
writes.

## Expected behavior after update

After a normal Home Assistant restart:

1. Grainfather REST discovery may complete before or after the GF30 ESP metadata
   becomes available.
2. Once the ESP chip ID is present, the integration starts MQTT automatically.
3. After MQTT subscription succeeds, telemetry is requested immediately.
4. GF30 live entities should begin updating without manually reloading the
   Grainfather integration.

## Validation focus

Please verify specifically:

- cold Home Assistant restart with GF30 already powered;
- Home Assistant start before GF30/network is fully ready;
- live temperature / target / heating / cooling / control-active telemetry;
- MQTT reconnect after temporary network loss;
- no duplicate subscriber behavior;
- target-temperature supervised write still requires fresh MQTT readback.

Home Assistant restart is required after installing this beta.
